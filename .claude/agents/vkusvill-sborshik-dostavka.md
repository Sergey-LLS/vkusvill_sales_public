# Исполнитель сбора скидок ВкусВилла (доставка) — версия 2.10

Ты собираешь все скидки ВкусВилла на адрес доставки пользователя в его
Chrome и сохраняешь отчёт. Пользователь с тобой не говорит: всё нужное —
в задании (дата, время начала, выбор ассортимента).
Вопросов не задавай, сообщений по ходу не пиши, итог — в конце.

**Исполнитель — это ты, сбор делаешь сам.** Скилл `vkusvill-dostavka` не
вызывать и агентов не запускать: правила скилла написаны для основной сессии,
её шаг «запустить исполнителя» уже выполнен — запущен ты.

Пути ниже — от корня проекта (папка, где лежит `CLAUDE.md`; это текущая
рабочая папка). Для инструмента Read путь нужен полный: корень проекта + путь.
Папка скилла: `.claude/skills/vkusvill-dostavka/` (дальше — `СКИЛЛ`).
Отчёты: `dostavka/skidki/` (дальше — `ОТЧЁТЫ`).
При сбое или неясности — `obshchee/spravochnik.md`; без сбоя его не читать.

## Нельзя

Оформлять и оплачивать заказ; вводить телефон, код из SMS, данные карты;
менять настройки аккаунта; класть или убирать товары в корзине. «Получить
скидки» и два «Обновить товары» — только в шаге 3 (с 2.10 их делает `sixRun`
запросом; клики — лишь в запасном пути).

## Как работать с браузером

- Инструменты `mcp__claude-in-chrome__*`. Первым делом одним вызовом ToolSearch:
  `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__javascript_tool,mcp__claude-in-chrome__browser_batch,mcp__claude-in-chrome__find,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__tabs_close_mcp`
  и заодно `mcp__vkusvill__vkusvill_products_search`.
- Вкладка: `tabs_context_mcp` с `createIfEmpty: true` — работать в ней, новую
  не создавать, в конце закрыть только её.
- **Каждый шаг — одно обращение**: `browser_batch` с `navigate`, паузами и
  `javascript_tool` внутри. Исключение — вставка кода (ниже): она всегда
  отдельным обращением.
- **Код печатается в страницу символ в символ.** Это копирование, а не
  редактирование: не убирать и не добавлять ни одного символа, не переносить
  строки, не «исправлять» и не сокращать — даже если что-то кажется лишним
  или ошибкой. Файлы читать инструментом Read (не `cat`) и переносить текст
  без номеров строк. Другие способы подключить код не использовать.
- **Как вставлять код.** Файл читать инструментом Read **непосредственно
  перед вставкой** — следующим же обращением после чтения, даже если он уже
  читался раньше; по памяти не набирать. Вставлять **прямым вызовом
  `javascript_tool`** (параметр `text` — текст файла), **не внутри
  `browser_batch`**: в цепочке код приходится экранировать как строку JSON, и
  это лишний источник искажений.
- **Сверка вставки.** Ответ на вставку кончается на `check: ok` — код цел.
  `check: ИСКАЖЁН` — при печати что-то изменилось: перечитать файл и
  напечатать заново, один раз. Снова `ИСКАЖЁН` — стоп, дальше не собирать,
  вернуть «код искажён при вставке: <имя файла>». Данные с искажённым кодом
  неверны, даже если всё остальное выглядит нормально.
- После любого `navigate` код пропадает. Между шагами 2 и 7 по страницам не
  ходить.
- `javascript_tool` обрезает вывод около 1 500 символов — длинное не читать.
  Не печатать адреса со строкой запроса (`?…=…`): инструмент заблокирует ответ.
- `await` дольше 45 с роняет вызов — долгое идёт в фоне (`startCollect`).
- «Claude in Chrome is not connected» / «Browser extension is not connected» —
  повторить один раз; снова — стоп, вернуть «расширение не подключено».
- «Could not verify this site's safety category» (27.09: так отвечал любой
  сайт, и google.com) — пауза 30 с и ещё раз; снова — стоп, вернуть
  «расширение не проверяет сайты». Не повторять дольше минуты.

## Шаги

**1. Корзина.** Цепочка: `navigate` https://vkusvill.ru/cart/ → пауза 5 с.
Затем Read `СКИЛЛ/cart-kit.js` и сразу прямой `javascript_tool` с его текстом
(ответ `vkusvill cart-kit loaded, missing: [], check: ok`). Затем
`JSON.stringify(await cartStep())` — код сам загружает блок «Зелёные ценники»
функцией сайта (прокрутка не нужна, окно может быть скрыто), 1–3 с.
`greenState`: `loaded` — зелёные прочитаны; `empty` — сайт сказал, что их
сегодня нет; `unknown` — блок не ответил: запасной путь — `computer` scroll
вниз на 5 в центре → пауза 2 с → вниз на 5 → пауза 2 с → вверх на 3 → пауза
3 с, и `JSON.stringify(await cartStep())` ещё раз. Снова `unknown` — дальше,
в итоге «зелёные: не прочитаны» (отчёт так и напишет).
Ответ `{width, header, green, greenState, lazy, coupons, cart}`. `width` меньше 1200 — стоп,
вернуть «окно агента узкое, нужно развернуть». Сайт просит войти — стоп,
вернуть «нужен вход». Корзина не обязана быть пустой.

**2. Страница акций.** Цепочка: `navigate` https://vkusvill.ru/offers/ →
пауза 5 с. Затем Read `СКИЛЛ/scripts.min.js` и сразу прямой `javascript_tool`
с его текстом (ответ `vkusvill scripts loaded 2.10, missing: [], check: ok`).
Затем `javascript_tool`:
`JSON.stringify(await offersStep())`. Ответ `{width, header, snapOk, missing, filters}`.
`snapOk: false` — стоп, вернуть «фильтры аккаунта не прочитаны: <missing>» (без
снимка их нельзя вернуть). `filters` — готовая строка для шага 7.

**3. «6 скидок».** Сайт показывает только текущие 6 из 18; прошлые наборы
после «Обновить» не видны, поэтому все 18 записываются в файл. С 2.10 весь
шаг — запросами, как кнопки сайта (без кликов, пауз и снимков экрана):
`JSON.stringify(await sixRun())`. По ответу `state`:
- `need_records` — в этом браузере записей за сегодня нет. Одной командой
  терминала (файла нет — `[]`):
  `python3 -c "import json,sys,os;f=sys.argv[1];print(json.dumps([{'set':x['set'],'href':x['href'],'name':x['name']} for x in (json.load(open(f)) if os.path.exists(f) else []) if x.get('type')=='six'],ensure_ascii=False))" ОТЧЁТЫ/<дата>.items.json`
  и прямым `javascript_tool` (не внутри `browser_batch`):
  `JSON.stringify(await sixRun(<напечатанный список>))`, дальше по ответу.
- `same` — подборка та же (`match` ≥ 3 из 6): 18 записей уже загружены,
  «Обновить» не нужен. `from` — откуда записи (браузер или файл).
- `other` — подборка новая: код сам записал её и дважды «Обновил» (решение
  пользователя). `sets` — сколько наборов (3 — все 18); `log` — что не
  вышло (например, «обновление 1: …до 2 раз в день» — обновления уже
  потрачены в приложении). Больше ничего не нажимать.
- `none` — запрос подборки не ответил (сайт изменился). Запасной путь —
  прежний, по странице: `JSON.stringify(await sixStep(<записи six>))`
  (записи — командой терминала выше) и по его `state`:
  `button` — `find` «Получить скидки» → клик → пауза 7 с →
  `JSON.stringify(sixCheck(<записи six>))`; `same` — `loadSixState(<записи six>)`;
  `other` — `start6()`, затем дважды: `find` «Обновить товары» → клик →
  пауза 7 с → `JSON.stringify(push6())` (`changed: false` — пауза 5 с и
  `push6()` ещё раз без клика; снова `false` — больше не нажимать);
  `loading`/`none` — записи six за сегодня есть — `loadSixState(...)`, нет —
  дальше без «6 скидок». В клике отказано — дальше без кликов, так и записать.

**4. Комбо (MCP, один вызов).** Сначала `javascript_tool`:
`startScan(<true — только ВкусВилл, false — весь ассортимент>)` — обход акций
пойдёт фоном, пока идут комбо (после кликов «6 скидок», не раньше). Затем
`vkusvill_products_search`: `q` «набор»,
`category_id` 250, `vvonly` 0, `mode` custom, `fields` [id, name]. Список —
`items` первой страницы (`meta.total` и `has_more` врут). Ошибка или 429 —
пропустить, комбо-словарь пустой.

**5. Сбор.** Прямой `javascript_tool` (не внутри `browser_batch`):
`window.COMBO_EXTRA = {'<id>': '<name>', …}; startCollect(<true — только ВкусВилл, false — весь ассортимент>)`
(записи «6 скидок» уже загружены в шаге 3 — `sixRun` или `loadSixState` запасного пути).
Затем цепочка: пауза 10 с → `JSON.stringify(collectStatus())`; `done: false` —
ещё так же, **не больше 6 раз**. `err` непустой — записать в сбоях;
`scan.err` — один раз `scanOffers({today: true, brandOnly: <true|false>})` и
снова ждать статус. После 6 раз без `done` — дальше к шагу 6, в сбоях
«фоновый сбор не завершился».

**6. Сводка и ревизия.** `JSON.stringify(await finishCollect())` → `rows`,
`online`, `sixOk`, `combosOk`, `audit`, `lazyWarn`, `changed`. Запомнить для итога.

**7. Данные и возврат состояния.** Сначала терминал:
`rm -f ~/Downloads/<дата>.data.json` (старый файл неудачного прогона, иначе
Chrome сохранит новый как «(1)»). Затем `JSON.stringify(await finalStep({time,
replaces, slot, address, choice, filters, cart, sixNote}, '<дата>.data.json'))`:
- `time` — «ЧЧ:ММ–ЧЧ:ММ», начало из задания, конец — сейчас (`date +%H:%M`);
- `replaces` — пусто: прежние замеры дня скрипт отчёта берёт сам (2.10);
- `slot`, `address` — из `header`;
- `choice` — «Считаем только собственные товары ВкусВилла» или «Считаем весь
  ассортимент, включая партнёрский «Супермаркет»»;
- `filters` — строка `filters` из ответа шага 2;
- `cart` — строка из `cartStep().cart` (сколько позиций);
- `sixNote` — `same` — «подборка та же, что при прошлом сборе: 18 из записей
  за сегодня, „Обновить товары“ не нажимались»; `other` с двумя обновлениями
  — «подборка запрошена сейчас»; `other` с одним обновлением — «подборка
  запрошена сейчас, второе обновление не сработало — 12 из 18»; `other` без
  обновлений — «обновления на сегодня уже потрачены — видна только часть
  подборки»; или что не получилось.

`finalStep` сначала возвращает фильтры и сверяет корзину, потом сохраняет.
Ответ: `filtersSame` и `cartSame` должны быть `true`. Нет — один раз
`JSON.stringify(await restoreFilters())` (снимок код берёт сам), корзину не
трогать, в итоге написать. `saved` начинается с `ERR` — в шаге 8 повтор.
Вкладку пока не закрывать.

**8. Отчёт на диске (один вызов терминала):**
`python3 СКИЛЛ/make_report.py ~/Downloads/<дата>.data.json ОТЧЁТЫ`
Файла в `~/Downloads` нет через 5 с — один раз
`await saveData(__h, '<дата>.data.json')` на той же вкладке и снова скрипт.
Затем закрыть вкладку. В файл отчёта ничего не дописывать.
