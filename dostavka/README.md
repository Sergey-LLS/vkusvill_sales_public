# ВкусВилл: доставка. Как это работает

**Версия 2.10.4-public.1 (публичная копия 2.10.4), 28 сентября 2026.** Сбор делает исполнитель на Sonnet за 6–7
минут. Проверена на настоящем сайте во всех условиях: корзина пустая и с
товаром; «6 скидок» — новая подборка (первый сбор дня 27.09: «Получить» и оба
«Обновить», 18 из 18) и та же (повторный сбор); зелёные ценники есть и «сегодня
нет». История версий — `istoriya.md` в папке скилла.

Главное по версиям: в «6 скидок» замены закончившихся товаров помечены «— замена», поэтому кандидатов бывает больше 18 (2.10.4); «6 скидок» — запросами, как кнопки сайта, без кликов и
пауз; записи дня хранятся и в браузере (2.10); возврат фильтров до
сохранения, шапка отчёта по факту проверки (2.9); предупреждение «⚠️ сайт
изменил загрузку блоков» (2.8); зелёные и «6 скидок» грузятся функцией самого
сайта, «сегодня нет» — только когда сайт так сказал (2.7); список по выгоде
(1.9); раскладка в корзину по вашему списку (2.0); подготовка за руку при
первом запуске (2.1).

Документ для чтения. Объясняет, что делает система, что ей нужно, кто в ней что
делает, как она проходит по сайту, сколько это занимает и почему, и чего она не
делает.

Сделан и проверен в Claude Code; в Codex и других агентах без адаптации не
заработает — что менять, в разделе 9.

Режима магазина — самовывоз и поход в зал — в этой копии нет: только доставка
на адрес, выбранный на сайте.

## 1. Что это такое

Система по одному запросу «что сегодня выгодного?» собирает **все скидки,
которые ваш аккаунт получит при доставке на ваш адрес прямо сейчас**, и отдаёт
один отчёт: отдельная таблица на каждый тип скидки, шапка с условиями замера,
примечания.

Два канала, через которые агент узнаёт про товары:

- **Ваш Chrome с открытым vkusvill.ru** — личный кабинет: адрес, остатки по
  этому адресу, персональные скидки, корзина. Всё, что «привезут мне и почём»,
  берётся только отсюда.
- **Официальный справочник ВкусВилла (MCP-сервер)** — состав, калорийность,
  рецепты, аналоги, список комбо-наборов. Он не знает, кто вы и где вы.

## 2. Кто что делает

В работе участвуют две модели.

| Кто | Модель | Что делает |
|---|---|---|
| **Основная сессия** — та, с которой вы говорите | Opus | задаёт вопрос про ассортимент, запускает исполнителя, по его итогу пишет вам сводку и отправляет файл; кладёт товары в корзину, если попросите |
| **Исполнитель** — субагент `vkusvill-sborshik-dostavka` | Sonnet | весь сбор в браузере: корзина, страница акций, «6 скидок», комбо, ревизия, возврат фильтров, файл отчёта. С вами не говорит, возвращает только итог |

Зачем так. Сбор — это длинная однообразная работа: много обращений к
браузеру, ожидания, печать кода. На Opus она стоила 11–13 минут и около
240 тысяч токенов. Sonnet делает то же самое за 5–6 минут и около 117 тысяч
токенов, а токен у него в два–два с половиной раза дешевле. Числа в отчётах при этом те же: это
сверено по спискам товаров между прогонами Opus и Sonnet.

Более дешёвая модель, Haiku, проверена 24 сентября и **не подходит**: в тестах
она искажала код при вставке, перепутала путь к файлу из задания и один раз
попыталась обойти запрет — такое предохранитель останавливает.

У исполнителя прямо запрещено вызывать скилл и запускать других агентов.
Причина — случай 24 сентября: исполнитель прочитал правила основной сессии
(«запусти исполнителя») и запустил сам себя, тот — ещё раз. Цепочку остановили,
на сайте никто ничего не сделал.

## 3. Что нужно, чтобы это работало

| Нужно | Зачем |
|---|---|
| **Google Chrome** (скачать: google.com/chrome; основным делать не нужно) | расширение Claude работает только в браузерах на Chromium; Safari не подходит. Проект проверен в Chrome |
| **Вход на vkusvill.ru в этом Chrome** | по номеру и коду из SMS, делаете вы сами |
| **Расширение Claude in Chrome** с входом в аккаунт Claude | это второй вход, отдельный от ВкусВилла |
| **Выбранный адрес доставки** | от него зависят ассортимент, цены и скидки |
| **Chrome запущен**, компьютер не спит | агент работает через браузер |
| **Chrome сохраняет файлы в «Загрузки» без вопроса** (`chrome://settings/downloads`: «Всегда указывать место для скачивания» выключено) | данные для отчёта приходят файлом в «Загрузки»; окно выбора папки остановит сбор |
| **Mac** | проект сделан и проверен только на macOS |
| **Сессия Claude открыта в папке проекта** (там, где лежит `CLAUDE.md`) | скиллы, исполнитель и подключение MCP лежат в ней; в другой папке их не будет |
| **Вход в Claude Code через `/login`**, подписка Pro, Max, Team или Enterprise | с ключом API браузерные инструменты не работают |
| **В терминальной версии Claude Code — `/chrome` → «Enabled by default»** | иначе браузер для сессии выключен; в приложении Claude не нужно |

Всё это при первом запуске агент перечислит сам, по шагам, и дождётся вашего
«готово» (см. раздел 4).

При первом запуске сессии в папке проекта Claude Code спрашивает, подключать ли
MCP-сервер ВкусВилла из файла `.mcp.json`. Его надо одобрить один раз.

Система рассчитана на **автоматический режим разрешений** Claude Code — он
включён у всех, ручной не рассматривается.

### Окно браузера: главное, что надо знать

Открывать vkusvill.ru для агента не нужно. Агент сам открывает себе
**отдельное окно Chrome** — это как вытянуть вкладку из браузера в своё окно,
только делает это расширение Claude. Вкладки в этом окне собраны в цветную
группу. Вход на сайт общий для всего Chrome, поэтому в этом окне агент уже
в вашем аккаунте.

**Выберите один из двух вариантов:**

| | Вариант 1 — проще всего | Вариант 2 — если браузер нужен вам самим |
|---|---|---|
| **Когда появилось окно агента** | Разверните его на весь экран. | Разверните его на весь экран. |
| **Во время работы** | Chrome не трогать вообще. | Окно агента не трогать. В других окнах Chrome работайте как обычно. |
| **Когда можно снова** | Когда в чате пришёл итог. | Когда в чате пришёл итог. |

«Не трогать окно агента» значит: не менять его размер, не сворачивать, не
перетаскивать на другой монитор, не закрывать и не переключать его вкладки,
ничего в нём не нажимать. Закрывать весь Chrome тоже нельзя — закроется и
окно агента.

«Итог» — это последнее сообщение работы: после сбора — сводка по скидкам,
после раскладки в корзину — «всё положил» или список расхождений. Сообщение
«сбор начат» — это ещё не конец.

Почему так строго. В узком окне сайт переключается на мобильную вёрстку, и
нажатия агента промахиваются мимо кнопок. 23 сентября это воспроизвелось
буквально: окно агента было маленьким и стояло за нижним краем экрана, клики
«В корзину» и «Удалить» не срабатывали. Если окно поменяет размер посреди
работы, вёрстка перестроится под ногами у агента, и клик по кнопке придётся
не туда.

**Как найти окно агента на Mac,** если оно открылось за другими окнами: меню
Chrome «Окно» — в списке оно с цветной группой вкладок. Разверните его зелёной
кнопкой в левом верхнем углу. При каждом новом сборе окно может открыться
заново — тогда развернуть снова.

**Страховка.** Исполнитель в начале работы измеряет ширину страницы. Если она
меньше 1200 пикселей, он останавливается ничего не сделав, и в чате приходит
просьба развернуть окно. Разверните, напишите «готово» — сбор начнётся заново.

Разворачивать ваше собственное окно не нужно: на работу агента оно не влияет.

**Два компьютера под одним аккаунтом Claude.** Расширение подключается к
аккаунту Claude, а не к компьютеру: сессия на любом компьютере под этим
аккаунтом видит Chrome на любом другом. 24 сентября это случилось на деле:
сессия на втором ноутбуке пошла в Chrome первого. Поэтому, работая на одном
компьютере, закройте Chrome на другом (или выйдите там из Claude в
расширении).

**Что нужно, чтобы передать систему другому человеку:** папка проекта целиком
(скиллы, исполнитель и `.mcp.json` лежат внутри) и Python 3 (на новом Mac macOS предложит поставить инструменты разработчика — агент подскажет).
Никаких ключей и сторонних репозиториев. Node нужен только тому, кто правит код
скилла: им пересчитывается отпечаток кода (см. раздел 6).

## 4. Как проходит один запрос

### Что видите вы

0. **При первом запуске — подготовка.** Если отчётов ещё нет, агент сначала
   одним сообщением проводит по шагам: поставить Chrome, если его нет,
   поставить расширение и войти в нём,
   в терминальной версии включить `/chrome`, войти на vkusvill.ru и выбрать
   адрес, держать окно агента на весь экран. Вы отвечаете «готово», он
   проверяет подключение и пишет «Всё, мы готовы к работе». Дальше — как
   обычно. Адрес агент берёт тот, что выбран у вас на сайте.
1. **Вопрос** — сразу, до любой работы: «только товары ВкусВилла или все,
   включая партнёрский „Супермаркет“». Без чисел. Задаётся при каждом сборе,
   даже повторном за день.
2. **Одна строка**: сбор начат, займёт несколько минут. Пока исполнитель
   работает, можно говорить о другом. Сообщений по ходу сбора нет — исполнитель
   работает в фоне.
3. **Сводка в конце**: если ревизия нашла изменения в типах скидок — этот блок
   первым; итог одной строкой (сколько позиций, по видам, зелёные); таблица
   «6 скидок» и таблица комбо; «На что обратить внимание» — как в файле; сбои,
   если были. Файл отчёта приходит отдельно, полные таблицы жёлтых и красных —
   только в нём. В конце — «назовите товары, которые положить в корзину».

### Что делает система

1. **Основная сессия задаёт вопрос про ассортимент** (если отчётов ещё нет —
   сначала подготовка, см. выше).
2. **Основная сессия запускает исполнителя** и передаёт ему только параметры:
   дата, время начала, ваш выбор ассортимента.

Дальше работает исполнитель:

3. **Корзина.** Вставляет в страницу маленький набор кода, берёт ширину окна,
   адрес, зелёные ценники (они видны только здесь), купоны и снимок корзины.
   Корзина не обязана быть пустой.
4. **Страница акций.** Вставляет основной код, снимает постоянные фильтры
   аккаунта.
5. **«6 скидок».** Одним запросом узнаёт текущую подборку и сравнивает с
   записанной за сегодня (как именно — ниже); новую — дважды обновляет тоже
   запросом. У всех кандидатов пометка проверяется по каталогу.
6. **Комбо-наборы.** Список из справочника ВкусВилла (один запрос к MCP).
7. **Сбор в фоне.** Обход страниц акций с фильтром «можно заказать сейчас»
   (жёлтые, оранжевые, красные ценники), кабинет (любимый продукт, ВкусБэк,
   бонусы, подписка, промокоды), цены составляющих комбо.
8. **Ревизия.** Сверка реестра из 13 акций с сайтом и витриной «Карта
   лояльности»; поиск незнакомых пометок, фильтров и блоков.
9. **Возврат состояния и данные.** Страница сохраняет все собранные данные
   одним файлом в «Загрузки», возвращает фильтры аккаунта как были и сверяет
   корзину со снимком.
10. **Отчёт.** Скрипт на компьютере собирает из данных отчёт
    `dostavka/skidki/<дата>.md` с разделом «На что обратить внимание» и
    служебный файл со ссылками на товары. Исполнитель возвращает основной
    сессии короткий итог.

Кнопок исполнитель не нажимает: «Получить скидки» и «Обновить товары» — это
запросы к сайту, и код отправляет их сам, ровно как кнопки (с 2.10). Клики
остались только запасным путём, если сайт этот запрос поменяет. Всё
читается из кода страниц, картинки не используются.

### Почему с «6 скидками» так сложно

Сайт никогда не показывает все 18 кандидатов сразу. «Получить скидки» даёт
6 товаров; «Обновить товары» убирает их со страницы и показывает 6 новых;
обновлений всего два в день, назад листать нельзя. Купить со скидкой при
этом можно любые 6 разных из всех 18. Поэтому, пролистав, агент записывает
все 18 в файл рядом с отчётом, а при следующем отчёте смотрит на страницу:

| Что вернул сайт на «Получить скидки» | Что это значит | Что делает агент |
|---|---|---|
| товары из записанных (хотя бы 3 из 6) | подборка та же | берёт записи дня (из браузера или из файла), «Обновить» не трогает; товар, заменивший закончившийся, дописывает |
| товары, которых в записях нет | новая подборка (первый отчёт за день) | записывает и дважды «Обновить» — 18 кандидатов |
| «обновить можно до 2 раз в день» на «Обновить» | обновления уже потрачены (например, в приложении) | записывает, сколько есть, и честно пишет это в отчёте |

«Получить скидки» ничего не тратит — это только показ последнего набора.
Записи дня лежат в файле рядом с отчётом и дублируются в браузере (по
аккаунту и дате): повторный сбор в том же браузере их не перепечатывает.
Пропали из браузера (очистка, другой профиль) — берутся из файла.

Ещё две особенности, которые агент учитывает:
- **Сравнение мягкое.** «Та же подборка» — если хотя бы 3 из показанных
  товаров есть среди записанных. Так агент не собьётся, если блок заменил
  закончившийся товар. Подборки разных дней не пересекаются вовсе.
- **Когда вы уже выбрали все шесть мест** (купили или положили в корзину),
  блок показывает только то, что вам ещё доступно, и карточек может быть
  меньше шести. Это те же товары из подборки — агент их узнаёт, а проверка по
  каталогу показывает, у каких скидка ещё действует.

Если запрос подборки не ответил, агент идёт прежним путём — по блоку на
странице и кликами; не вышло и так, а подборка за сегодня записана — берёт её
из записей и проверяет каждый товар по каталогу. Отчёт не останется без
«6 скидок», а если «6 скидок» в сборе не собрались, записи дня не стираются.

### После отчёта: список по выгоде и корзина

**«Разложи по выгоде».** Все позиции отчёта одной таблицей — от самой большой
выгоды в рублях к самой маленькой, с видом скидки так, как его называет
ВкусВилл («Скоро исчезнут с полок (красный ценник)», «Скидка по карте (жёлтый
ценник)»), остатком и условиями. Весовые товары — отдельной таблицей «выгода
на 1 кг»: скидка на них действует на любой вес, если в условиях не указан
минимальный. Делает скрипт на компьютере за секунду, браузер не нужен. Файл
`<дата>.vygoda.md` рядом с отчётом, отчёт за день не меняется.

**«Положи в корзину».** Вы называете товары из сегодняшнего отчёта словами.
1. Агент находит их в отчёте. Если просите больше, чем было на момент замера,
   сразу говорит: «в отчёте на 00:43 — 10 шт». Если из «6 скидок» выбрано
   больше шести разных, предупреждает, что седьмой ляжет без скидки. Ждёт
   ответа только при таком расхождении.
2. Запоминает, что было в корзине до этого, — чтобы по вашей просьбе вернуть
   как было.
3. Кладёт по вашему списку и после каждого товара смотрит на счётчик. Если
   нужно больше одной штуки, вписывает число; не сработало — доводит
   кнопками «−»/«+» по одному нажатию с проверкой (27.09 товар сначала
   лёг 5 шт вместо 2 — агент сам убрал лишние три). Где товара меньше, чем
   просили, берёт сколько есть: сайт сам не даёт положить больше остатка
   (проверено 24.09). Товар не из отчёта тоже можно попросить — агент найдёт
   его в каталоге (проверено 27.09).
4. Проверяет корзину по данным сайта и пишет коротко в чате, без файла: всё
   сошлось — «всё положил»; нет — только расхождения, по строке: «Кока-кола:
   просили 10, положил 7 — больше нет», «Моцарелла — 0, закончилась», где
   скидка не применилась. В конце — позиций, сумма, экономия.
5. Заказ оформляете и оплачиваете вы.

Это делает основная сессия, а не исполнитель: класть в корзину исполнителю в
фоне предохранитель Claude Code запрещает. Во время раскладки окно агента не
трогать — правила те же, что при сборе (раздел 3).

## 5. Типы скидок и как каждый находится

Реестр из 13 акций сверен с официальной витриной ВкусВилла «Карта лояльности».

| Тип | Как находится |
|---|---|
| **Жёлтые** «Специальная цена», по карте | пометка «Скидка по карте лояльности по ДД.ММ» на карточке; вариант «только онлайн» при доставке работает, помечается `[онлайн]` |
| **Оранжевые** «Больше — выгодней» | пометка «При покупке от N шт/кг» |
| **Красные** «Скоро исчезнут с полок» | пометка «Исчезающий вид», срока нет |
| **«6 скидок»** −20% на 6 разных товаров в день | блок на странице акций, до 18 кандидатов; у каждого проверяется пометка в каталоге |
| **Зелёные ценники**, уценка от −40% | только блок в корзине; считаются карточки, не текст |
| **Любимый продукт** | блок в кабинете: доступен ли, условие, период |
| **ВкусБэк** | блок в кабинете: процент, куплено, оценено |
| **Бонусы** | баланс в шапке кабинета |
| **Подписка на скидку** | подключена или нет |
| **Купоны** | текст в корзине, клик не нужен |
| **Промокоды** | страница промокодов; это коды для друзей, себе применить нельзя |
| **Кешбэк на отдельные товары** | **проверить нечем**: как отметка выглядит на карточке, неизвестно, ни разу не попадалась. В отчёте так и пишется |
| **Комбо-наборы** | справочник ВкусВилла, категория «Комбинированные наборы», плюс «Кофейные пары» с сайта; выгода = сумма составляющих минус цена набора; подозрительная выгода в таблицу не идёт |

Синие ценники — новинки, не скидка, в отчёт не входят. Скидки между собой не
складываются: действует та, что выгоднее.

### Если типы скидок изменились

Ревизия идёт в конце сбора. Если ВкусВилл переименовал, убрал или добавил тип
скидки, или на карточках появилась незнакомая пометка, в отчёте появляется
блок **«🔴 Изменения в типах скидок»** сразу после шапки, и в чате он идёт
первым. Товары под незнакомый тип агент не собирает: как их собирать, решается
вместе с вами.

Настоящих изменений пока не было. Одна ложная тревога — 24 сентября: в код
корзины всегда зашито скрытое окно благотворительности (наборы продуктов для
фонда, у каждого подпись «Состав набора»), и в одном наборе было «Молоко 2,5%».
Ревизия ищет в заголовках в том числе знак «%» и приняла эту строку за новую
акцию. С версии 1.8 окно фонда ревизия не читает. Названия обычных товаров,
вроде «Сметана 20%», в эту проверку не попадают вообще: заголовки ищутся
только в кабинете и корзине, а товары там в этот момент не загружены.

## 6. Сколько это занимает и почему

Полный сбор — **6–7 минут и около 110–130 тысяч токенов** исполнителя
(26–27.09: повторный сбор 6,7 мин, первый сбор дня 7 мин). Сверху — немного
работы основной сессии: вопрос, запуск, сводка. Бывает дольше, если в это
время медленно отвечает сама модель: 26.09 одна печать кода заняла 8 минут
вместо 2.

| Что | Примерно | Почему |
|---|---|---|
| Печать кода в страницу | около 2,5 минуты | ~6 тыс. знаков на корзине и ~29 тыс. на странице акций (сжато), модель набирает текст целиком — см. ниже |
| Ожидания на сайте | около минуты | загрузка страниц, обход акций и проверка кандидатов в фоне |
| «6 скидок» | секунды | запросы вместо кликов; записи дня из браузера |
| Обращения к инструментам | 26–31 штука по несколько секунд | перед каждым модель перечитывает всё, что было до него |
| Чтение инструкции | секунды | файл исполнителя, около 15 КБ |
| Сборка отчёта | секунды | делает скрипт на компьютере, модель не печатает ни строки |

**Что такое «вставка кода».** Сайт нельзя читать снаружи: прямой запрос с
компьютера он отклоняет. Расширение умеет только смотреть на открытую страницу
и запускать в ней код. Поэтому весь сбор делает программа, которую агент
запускает внутри открытой страницы: она сама загружает нужные адреса и
разбирает их. Передать файл в страницу нельзя, и буфера обмена у модели нет —
«Ctrl-C, Ctrl-V» для неё означает перепечатать весь текст символ за символом.

**Почему не иначе.** Все способы запустить код, который модель не напечатала
сама, в автоматическом режиме Claude Code закрыты предохранителем, и это
проверено: загрузка по ссылке из интернета (отказ «Code from External»),
сохранение кода в хранилище браузера и запуск одной строкой, подготовка кода
обработкой в терминале (оба — отказ «Auto-Mode Bypass»). Предохранитель
нарочно требует, чтобы модель запускала только то, что видела и напечатала.

**Как проверяется, что код не исказился.** Последняя строка кода сама считает
его отпечаток и сравнивает с эталоном: ответ «check: ok» — код цел,
«ИСКАЖЁН» — при печати что-то изменилось. Тогда исполнитель перепечатывает
файл один раз; искажён снова — останавливается, данные с искажённым кодом не
собираются. Проверка появилась после первого прогона Sonnet 23 сентября, когда
он молча переписал слова в коде и отчёт вышел неверным.

**Почему сейчас быстрее, чем в версии 1.6.** В 1.6 первая вставка большого
файла срывалась оба раза, и файл приходилось печатать два-три раза — это 4–5
лишних минут. Тест 24 сентября показал, что сама модель копирует точно
(9 вставок из 9 целые), а срывается только в полном прогоне: файл прочитан
задолго до вставки, и код шёл внутри цепочки команд, где его надо экранировать.
С версии 1.7 исполнитель читает файл прямо перед вставкой и вставляет его
отдельным вызовом. Оба прогона после этого — с первого раза.

## 7. Чего система не делает

- Не оформляет и не оплачивает заказ, не вводит номер, код из SMS, данные
  карты, не меняет настройки аккаунта.
- Не кладёт товары в корзину без вашей просьбы. По просьбе кладёт основная
  сессия, положенное остаётся в корзине; «верни как было» откатывает к тому,
  что лежало до этого.
- Не оформляет заказ, даже когда корзина собрана: это всегда делаете вы.
- Не обещает, что товар доедет: остатки меняются в течение дня и зависят от
  слота.
- Не показывает партнёрские товары, если вы ответили «только ВкусВилл».
- Не находит кешбэк на отдельные товары: признак неизвестен.
- Не обходит весь каталог (около 11 тысяч позиций) без вашей явной просьбы.

Ваш выбор, который агент не отменяет сам: подборку «6 скидок» запрашивать и
обновлять без вопроса, раз в день; один отчёт в день; корзину пустой не
требовать; вопрос про ассортимент задавать первым и каждый раз, без чисел;
в чате — короткая сводка, полные таблицы — в файле; у товаров нет кодов,
проценты со знаком («−10%»); комбо без слова «Комбо» включать, если выгода
реальная.

## 9. Если у вас Codex (или другой агент)

Проект можно перенести, но это **не проверено**: всё ниже — план адаптации, а
не готовая инструкция. Каждый шаг проверять на настоящем сайте, по одному.

| Что в Claude Code | Что сделать в Codex |
|---|---|
| Инструкции проекта в `CLAUDE.md` | Codex читает `AGENTS.md`. Когда адаптация готова, заменить текущий `AGENTS.md` (сейчас в нём предупреждение «не запускать») указателем на `CLAUDE.md` и `SKILL.md` плюс отличиями для Codex |
| Скилл `.claude/skills/vkusvill-dostavka/SKILL.md` подключается сам | Попросить агента прочитать этот файл напрямую или сослаться на него из `AGENTS.md` |
| MCP ВкусВилла в `.mcp.json` | Подключить тот же сервер `https://mcp.vkusvill.ru/mcp` (без авторизации) в настройках Codex — формат по его документации |
| Браузер: расширение Claude in Chrome | **Главное.** Нужен инструмент, который управляет Chrome и умеет выполнять код в странице и кликать, — например, MCP для браузера (Playwright, Chrome DevTools). Вход на vkusvill.ru нужен в том браузере или профиле, которым он управляет |
| Исполнитель на Sonnet (`.claude/agents/…`) | Такого механизма нет — сбор ведёт сама сессия. Шаги сбора брать из файла исполнителя: он написан как пошаговая инструкция |
| Код в страницу — только печатью целиком (ограничение Claude Code) | У другого инструмента свои правила: возможно, код можно подключать проще. Выяснять на месте |

**Работает без изменений:** код для страницы (`scripts.min.js`,
`cart-kit.js`), сборка отчёта `make_report.py`, список по выгоде
`vygoda.py` — это обычный JavaScript и Python. Справочник по сайту
`obshchee/spravochnik.md` тоже годится как есть.

**С чего начать проверку:** вставить `cart-kit.js` на странице корзины и
получить ответ `check: ok` — значит, браузерный инструмент подходит. Дальше —
по шагам исполнителя, после каждого сверяясь, что фильтры аккаунта и корзина
не изменились.

Запреты те же в любом агенте: не оформлять и не оплачивать заказ, не вводить
телефон, код из SMS и данные карты, не менять настройки аккаунта.
