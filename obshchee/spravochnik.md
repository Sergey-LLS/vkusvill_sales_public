# Справочник: как устроен vkusvill.ru и акции

Факты про сайт и механику, на которые опираются правила в SKILL.md. Даты —
когда проверено. Правила здесь не живут; если что-то расходится с SKILL.md,
прав SKILL.md.

## Страница акций `/offers/`

- Страницы `/offers/?PAGEN_1=N` приходят готовым HTML. Без фильтров ~33
  страницы по 24 карточки (≈780 позиций «только ВкусВилл», 79 страниц ≈ 1 900
  со всем ассортиментом). Грузить `fetch` в фоне изнутри страницы: прямой
  запрос с компьютера сайт отклоняет, а синхронный обход через CDP ловит
  тайм-аут 45 с.
- Поля карточки `.ProductCard`: `.ProductCard__link` (имя, href с id в конце
  `-12345/`), `.js-datalayer-catalog-list-price`, `…-price-old`, `.Price`
  (единица `/шт`, `/кг`), `.ProductCard__notice` (пометка скидки),
  `.ProductCard__Rest` («В наличии N шт», «В наличии 0.855 кг»),
  `.js-datalayer-catalog-list-category`.
- Среди карточек бывают заготовки без имени и цены (23.09: 48 на 183 настоящих)
  — считать только карточки с именем и ценой.
- Имя товара. Внутри `.ProductCard__link` два span: `.js-product-v-tizer__title-text`
  (имя, иногда с граммовкой) и `.ProductCard__linkWeight` (граммовка или цена за
  кг). Текст всей ссылки их склеивает («…, 150 г, 150 г», «…, 2 708 ₽ / кг»),
  атрибут `title` — имя без граммовки, на живой странице текст ещё и обрезан
  многоточием. `cardName()` берёт первый span; `read6` (живой блок «6 скидок») —
  `title`. Имена на сайте без «ё» и в прямых кавычках; в отчётах ставим «ё» и
  «ёлочки».
- Принадлежность адресу определяет строка остатка: сайт отдаёт акции всей сети,
  «В наличии» стоит только у того, что привезут на выбранный адрес. Наличие
  зависит и от слота: быстрая доставка — только склад сейчас, слот позже — шире.

### Фильтры работают только с `sf4=Y`

Без `sf4=Y` параметры молча игнорируются (проверено 23.09).

| Адрес | Что отдаёт |
|---|---|
| `/offers/?F[DEF_2]=1&sf4=Y` | только то, что можно заказать сейчас: 8 страниц вместо 33, все карточки «В наличии» |
| `/offers/?F[212][]=284&sf4=Y` | красные «Скоро исчезнут» |
| `/offers/?F[212][]=278&sf4=Y` | жёлтые по карте |
| `/offers/?F[212][]=281&sf4=Y` | оранжевые от N шт |
| `F[DEF_2]=1` + `F[212][]=…` | пересечение: 2 страницы вместо 24 |

Точность быстрого способа проверена одновременным замером: 7–8 страниц с
`F[DEF_2]=1` и полный обход 33 страниц с фильтром «В наличии» у себя дали
одинаковые списки до штуки.

### Постоянные фильтры — ловушка

Блок «День заказа и ассортимент» хранит настройки **на аккаунте** и молча
применяет их к голому `/offers/`: `DEF_2` «Можно заказать сегодня», `DEF_3`
«Только товары ВкусВилл», `DEF_5` веганские, `DEF_6` без сахара. Поля —
`input[name="F[DEF_N]"]`, id `FILTER4_N`. У пользователя включён **`DEF_3`**.

Любой запрос с `sf4=Y` **перезаписывает** сохранённый набор — поэтому перед
сбором `readFilters()`, после — `restoreFilters(снимок)`.

Партнёрский ассортимент («Супермаркет»: Barilla, Borjomi, Бондюэль, «Святой
источник», «Вологодский пломбир») бывает только при доставке. Замер 23.09 на
тестовый адрес: 920 акционных позиций со всем ассортиментом против 175 только
ВкусВилл, из них «Супермаркет» 664. При самовывозе списки со снятым и
поставленным `DEF_3` совпали (159 и 159).

## Механика «6 скидок» (проверено на аккаунте 21–23.09.2026)

Блок «Скидка 20% на 6 товаров» вверху `/offers/`; отдельная страница
`/offers/prod6/` грузится скриптом, `fetch` отдаёт пустые карточки. Кнопка
`VV23_6ProdsAuthorized__UpdateBtn` шлёт POST `/ajax/inset_6prods.php`.

- В начале дня блок показывает текст «Каждый день новая подборка…» и кнопку
  «Получить скидки» — подборку надо запросить.
- Показывают 6 товаров. «Обновить товары» меняет набор до 2 раз в день, итого
  до 18 кандидатов. Лимит обновлений сбрасывается на следующий день.
- Лимит скидки — **6 разных товаров в день**: считаются и купленные сегодня, и
  лежащие в корзине. Несколько штук одного товара — одно место. Купленный со
  скидкой товар можно брать со скидкой снова. Место достаётся тому, кто попал в
  корзину раньше; седьмой — по обычной цене; убрал из корзины — место
  освободилось, после покупки — нет.
- Блок и карточки показывают **кандидатов, а не бронь**: пока есть свободное
  место, пометка −20% висит у всех кандидатов; когда 6 мест заняты, остаётся
  только у занявших.
- К прошлым наборам в блоке вернуться нельзя, но их товары ищутся в каталоге по
  названию и сохраняют пометку. Единым списком нигде не собраны — записывать
  наборы сразу.
- Исчерпанный лимит обновлений: кнопка на месте, тост «Заменили товары в
  подборке» появляется, набор не меняется. По виду кнопки судить нельзя.
- **Блок умеет врать:** через несколько часов снова показывает «Получить
  скидки», хотя подборка выдана (23.09: запрошена в 02:10, в 10:30 блок выглядел
  нетронутым, при этом все 18 держали пометку в каталоге). Признак, что работа
  сделана, — файл отчёта за сегодня. Подтверждено 24.09 дважды: у
  пользователя подборка 00:17 к 13:55 «пропала», у второго аккаунта подборка
  14:38 к 15:12 тоже; нажатие «Получить скидки» в 15:28 показало ровно третий
  набор 14:38, обновления не сработали (лимит потрачен), а все наборы 14:38
  держали пометку «6 скидок -20%» в поиске. Нажимать «Получить скидки» при
  готовой подборке безопасно — это просто показ последнего набора.
- **Запросы вместо кнопок (найдено 26.09, 2.10).** Обе кнопки — POST
  `/ajax/inset_6prods.php` с `USER_ID` (`#lk-user-id`) и `command`:
  «Получить скидки» (`.js-inset-6prods-get`) — `getTovAbonement`, только
  показ текущего набора; «Обновить товары» (`.js-inset-6prods-update`) —
  `updTovAbonement`, тратит обновление. Ответ JSON `{success, html,
  error_text}`, в `html` шесть `.ProductCard`. Лимит исчерпан — `success:
  "N"`, «…обновить подборку товаров можно до 2 раз в день» (проверено).
  Страница товара показывает пометку «6 скидок -20%» и «В наличии N шт».
- Блок ленивый: заглушка `.js-section-block-lazy._ni[data-code="6skidok"]`;
  сайт грузит его функцией `updateLazyItems`, когда заглушка попадает на
  экран. **С 2.7 (25.09) `loadLazy('6skidok')` вызывает её напрямую** — блок
  с кнопками встаёт без прокрутки и в скрытом окне. История: 24.09 без
  прокрутки мышью заглушки стояли бесконечно, `scrollBy` из кода не помогал
  (наблюдатель сайта не срабатывает, если блок не показан). Прокрутка — только
  запасной путь. Читать блок, когда у всех шести есть ссылка на товар.
- В общем списке `/offers/` (78 страниц, 24.09) пометки «6 скидок» нет ни у
  одного товара — только в поиске `/search/`. Собрать 18 без листания
  нельзя.
- Новая подборка — с началом суток: 24.09 в 00:17 «Получить скидки» дала 18
  товаров, ни одного из вчерашних (подборки разных дней не пересекаются).
  Точный час не измеряем и не опираемся на него: агент сравнивает видимое с
  записанным в файле. Не проверено, есть ли ограничение на количество штук
  одного товара.
- Проверка корзиной 21.09: куплено 5 разных → шестой в корзине −20%, седьмой
  без скидки; убрал шестого — седьмой получил скидку.

## Зелёные ценники

Только в корзине `/cart/`, блок «Зелёные ценники» под «Добавьте в заказ».
Блок ленивый: заглушка `.js-section-block-lazy._ni[data-code="cart_green_labels"]`
с `data-func="initLazyGreenLabelsSlider"` → POST `/ajax/index_page_lazy_load.php`
(`code=cart_green_labels`). **С 2.7 (25.09) `loadLazy` вызывает функцию
напрямую** — 1–3 с, без прокрутки и в скрытом окне. Загрузился пустым —
виден `#js-Delivery__Order-green-state-empty` (настоящее «сегодня нет»).
История: 25.09 `scrollIntoView` и прокрутка вниз-вверх давали ложный 0
(блок не попадал на экран — при пустой корзине он ниже, ~1400 px). Карточки — элементы
`data-is-green="Y"`, остаток уценённой партии — `data-max` (22.09 у всех 2).
Заготовка «Зелёных ценников сейчас нет» лежит в коде всегда — судить только по
числу карточек. В каталоге у того же товара обычная цена и обычный остаток.
Онлайн их 0–5 (овощи, зелень, выпечка), в зале больше. MCP их не видит.
Появляются в течение дня: 27.09 в 11:00 сайт отдал пустой блок (признак
«пусто» открыт им самим), а к ~11:20 появился лук репчатый. До загрузки
элемент «пусто» скрыт — ложного «сегодня нет» от раннего чтения не бывает
(проверено 27.09). Отчёт — снимок на время замера; новые зелёные подхватит
повторный сбор.

## Программы кабинета `/personal/`

Читать текст блока `main`.
- Любимый продукт — 1 товар −20% «на завтра», менять можно каждый день;
  условие — покупки вчера и сегодня > 500 ₽; период указан («по 28.09»).
  Кнопка «Выбрать в каталоге» меняет аккаунт — только по просьбе.
  Правила (`/offers/lyubimyy-produkt.html`, 24.09): скидка 20% на выбранный
  товар 7 дней, начинает действовать **со следующего дня**; менять можно
  каждый день при покупках от 500 ₽; новичкам (первая карта) — сразу и без
  условия. Нельзя выбрать: партнёрские разделы (Аптека, Рестораны,
  Зоотовары, Супермаркет), вино и крепкий алкоголь, товары дешевле 11 ₽,
  предсобранные наборы. Складывается с подпиской и ВкусБэком. Под товаром
  «Подобрали для вас»: «Могут понравиться» (из чего выбирать) и «Совсем как
  Любимый» — замены, если любимый раскупили, их тоже можно купить с −20%.
  **Выбранный товар в `/personal/`** (проверено 24.09):
  колонка `.VV22_LKSpecialsTills__Col._LP`, внутри
  `.lk-specials-col__lp-with-prod`; слов «Любимый продукт» в тексте блока
  **нет** — «С завтрашнего дня по 01.10», название со ссылкой `/goods/…`,
  цена со скидкой и зачёркнутая («197.60 ₽/шт 247 ₽»), «Подобрали для вас»
  (кнопка-окно), «Назначить новый», «В наличии 22 шт»; `data-id` — код
  товара. До начала действия на странице товара цена обычная (247), сердечко
  «Любимый продукт» закрашено. Когда скидка действует (аккаунт с активным
  любимым, 24.09): на `/offers/` фильтр «Любимый продукт и замена», на
  карточках пометка «Любимый продукт - N%», в кабинете блок ВкусБэка
  «Увеличьте кешбэк с 3% до 5%».
- ВкусБэк — кешбэк 3–10% на следующий месяц за N разных товаров и M оценок,
  счётчик в блоке.
- Промокоды `/personal/my_promocodes/` — реферальные, для друзей (−500 ₽ от
  2 500 ₽, −300 ₽ от 1 500 ₽ на первый онлайн-заказ), пользователю 700 бонусов
  за друга.
- Бонусы — баланс в карточке `.VV_PersonalSB20Card._bonuses` (число — `__Desc`), тратятся до 100% покупки, включая акционные товары. Тысячи сайт делит узким пробелом U+2009 («2 900 руб»).
- Подписка на скидку — 490 ₽ на 31 день, −10% на 17 категорий, действует со
  следующего дня, не на супермаркет, мясо и птицу, овощи-фрукты, алкоголь;
  считается от итога чека после Любимого продукта и цветных ценников; с
  ВкусБэком не складывается. У пользователя не подключена. На `/card/` её нет —
  проверяется по `/offers/podpiska-na-skidku.html`.
- Кешбэк на отдельные товары — отметка на карточке, возврат бонусами после
  статуса «Успешно завершён». **Как отметка выглядит в коде — неизвестно**:
  22.09 и 23.09 слов «кешб» и «бонус» на акционных карточках не было. Когда
  попадётся — записать селектор сюда.
- Купоны — `/cart/` → «Применить купон или промокод» → вкладка «Купоны». Блок и
  текст «Купонов пока нет» есть в HTML всегда, товар в корзине и клик не нужны.

## Корзина `/cart/`

`basketPageData` лежит в HTML как `JSON.parse('…')` — `readBasket()` читает без
перехода. Проверено 23.09 с товаром в корзине: пустая корзина — `basket: []`,
непустая — объект с ключами `<PRODUCT_ID>_0`. Поля позиции: `PRODUCT_ID`, `Q`
(количество), `NAME`, `PRICE` (со скидкой), `BASE_PRICE`, `DIFF_PRICE` (размер
скидки), `UNIT`, `MAX_Q`, `IS_GREEN` (0/1), `IS_LP` («N»/«Y», любимый продукт),
`PRICE_LABEL`, `CAN_BUY`, `CATEGORY`. Кандидат «6 скидок» в корзине показывает
`PRICE` 83 при `BASE_PRICE` 104 и `DIFF_PRICE` 21 — так видно, что место занято.
Текст страницы про корзину врёт («корзина пуста» при товарах) — судить по данным.

Больше остатка положить нельзя (проверено 24.09, основная сессия, по просьбе
пользователя: «Игровой набор „Зимние фантазии“», в наличии 1 шт). На странице
товара «В корзину» даёт 1 шт, после этого «+» бледный и не срабатывает. В
корзине у позиции `Q` 1, `MAX_Q` 1, под счётчиком «В наличии: 1 шт»; `PRICE`
36, `BASE_PRICE` 180, `DIFF_PRICE` 144 — скидка видна по данным. Удаляет
позицию значок корзины-мусорки у счётчика (строка сереет, кнопка «Вернуть»,
после перезагрузки `basket: []`); крестик в правом верхнем углу строки
позицию не убрал. Что будет, если остаток упадёт уже после того, как товар
лёг в корзину, не проверено: смотреть `Q` против `MAX_Q`.

Живая раскладка 24.09 (гель 10 при 6, десерт 11 при 9 — в отчёте было 11,
конфеты «Пралине» 1 кг при 0,855 кг): количество вписывается в счётчик кнопки
(поле `CartButton__selector--input`, тройной клик, число, Enter) и на странице
товара, и в корзине; больше остатка сайт не ставит — 6, 9 и 0,86 кг, подсказка
«Добавлено максимальное количество». Частые нажатия «+» теряются (9 нажатий с
паузой 1 с дали +4). Весовой товар по «В корзину» ложится 0,21 кг. Вписанный 0
позицию не удаляет; мусорка у счётчика есть только при 1 шт. «Очистить
корзину» над списком спрашивает «Вы точно хотите очистить корзину?» — «Да».
В корзине с товарами внизу кнопка «Заказать за N ₽» — не трогать.

Окно «Выгодное комбо» (`#js-vv-modal-product-combo`, кнопка
`.js-show-combo-modal` у позиции с `is_combo` и `CAN_BUY=Y`) в коде есть, но
22.09 у всех наборов `is_combo` был пуст — механизм не включён.

Замер 23.09: «Пюре из абрикоса» с пометкой «По карте лояльности … только
онлайн» в корзине доставки — 222 ₽ при базовой 252 ₽, «−30 ₽». Скидка «только
онлайн» при доставке проходит.

## Комбо-наборы

Отдельные товары, скидка встроена в цену: пометки, зачёркнутой цены и места на
`/offers/` нет. Эталонный список — MCP `vkusvill_products_search`,
`category_id=250` «Комбинированные наборы» (23.09: 5 наборов, два без слова
«Комбо» — «Набор: Салат Витаминный + Плов с курицей» и «Сосиски куриные с
картофельным пюре и салат винегрет»). На сайте такой категории нет: в хлебных
крошках эти товары лежат в «Особом питании» и «Готовой еде», а поиск по слову
отдаёт их нестабильно. «Кофейные пары» (`Комбо "Кофейная пара" … 2х300 мл`) в
категории 250 нет — `comboCards()` берёт их из поиска «комбо». Выгода 23.09:
от −30 (−7%) до −136 ₽ (−27%).

## Переключение точки (адреса или магазина)

Из JS точку переключить нельзя: программный клик по радиокнопке ставит
`checked`, «Выбрать» нажимается, но приложение событие не принимает. Клик по
`ref` строки тоже не выбирает — нужен настоящий клик точно в кружок.

Координаты берутся из DOM. Тулу нужны пиксели его кадра, `getBoundingClientRect()`
даёт CSS-пиксели; между ними множитель без сдвига, который меняется вместе с
окном (23.09: 0,941 и 1,357 в одной сессии). Запоминать нельзя — мерить зондом:

```js
// 1) перехватчик: гасит клик и записывает, куда он пришёл
window.__cal = {hits: []};
window.__calH = e => { __cal.hits.push([e.clientX, e.clientY]);
  e.preventDefault(); e.stopPropagation(); };
['mousedown','mouseup','click'].forEach(t => addEventListener(t, __calH, true));
// 2) кликнуть тулом в две точки, например (191,13) и (400,300)
// 3) снять перехватчик и посчитать
['mousedown','mouseup','click'].forEach(t => removeEventListener(t, __calH, true));
const [a, b] = [__cal.hits[0], __cal.hits.at(-1)];
window.KX = (400 - 191) / (b[0] - a[0]), window.KY = (300 - 13) / (b[1] - a[1]);
window.pt = e => { const r = e.getBoundingClientRect();
  return [Math.round((r.left + r.width/2) * KX), Math.round((r.top + r.height/2) * KY)]; };
```

Проверять, что `hits` не пуст (клики в (200,150) и (700,500) событий не дали,
(191,13) и (400,300) — дали). Скриншоты могут падать по тайм-ауту — зонд от них
не зависит.

Порядок и сверка после каждого клика:

| Шаг | Как | Что должно стать правдой |
|---|---|---|
| кнопка адреса в шапке | `find` + клик по `ref`; **сначала проверить, не открыта ли модалка** — кнопка работает как переключатель | `document.querySelector('.VV_RadioList')` есть |
| вкладка «Доставка» / «Самовывоз» | `pt()` от `button.VV_SegmentedControl__Item` с ненулевой шириной | в списке строки нужного типа |
| строка адреса или магазина | `<input type=radio>` нулевого размера; брать `li.VV_Radio` с ненулевой шириной, клик по `left + 18` | у строки `input.checked === true` |
| «Выбрать» | `pt()` от видимой кнопки | окно слотов (`/Ассортимент зависит/`) |
| крестик окна слотов | `pt()` от `.VV_ModalCloser` | **шапка показывает новую точку** — единственный надёжный признак |

Не сошлось — скриншот и доделать по нему; два промаха подряд — пристреляться
заново. После смены точки страница перезагружается, `window` пустеет.
