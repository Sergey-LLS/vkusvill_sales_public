# Проект «ВкусВилл»: скидки с доставкой в аккаунте пользователя

Папка самодостаточна: скилл, исполнитель, код, отчёты и подключение MCP лежат
здесь. Снаружи нужны только Google Chrome с расширением Claude in Chrome и вход
на vkusvill.ru — их делает сам человек.

## Что умеет

Один режим — доставка на адрес, выбранный на сайте. Скилл `vkusvill-dostavka`:
«что сегодня выгодного» (отчёт по всем скидкам за день), «разложи по выгоде»
(список от большей выгоды к меньшей), «положи в корзину» (по списку
пользователя). Самовывоза и режима магазина в этом проекте нет.

## Где что

```
.claude/skills/vkusvill-dostavka/   правила доставки, код для страницы, сборка отчёта
.claude/agents/                     исполнитель-субагент: модель и шаги сбора
.mcp.json                           MCP-сервер ВкусВилла (официальный, без авторизации)
obshchee/                           справочник сайта и отчёт о MCP
dostavka/skidki/                    отчёты: <дата>.md, <дата>.items.json, <дата>.vygoda.md
```

`dostavka/README.md` — объяснение для человека, не инструкция для агента.

## Первый запуск

Если в `dostavka/skidki/` нет ни одного отчёта `*.md` (проверить `ls`), на
любое первое сообщение человека (даже «привет») вызвать скилл
`vkusvill-dostavka` и отправить сообщение из его этапа подготовки (раздел 4):
что умеет, что нужно, какие шаги. Отчёты есть — работать как обычно.

## Нельзя никогда

Оформлять и оплачивать заказ; вводить телефон, код из SMS, данные карты;
менять настройки аккаунта. Корзину менять — только в основной сессии по
просьбе пользователя: снимок до правки, откат по просьбе; тестовые правки —
всегда с возвратом как было. Код в страницу — только печатью файла целиком:
загрузку кода по ссылке и запуск кода из хранилища браузера предохранитель
автоматического режима считает обходом. Данные (записи «6 скидок» за день)
в хранилище браузера держать можно — это не код.

## Как работаем над проектом

- Проверять только на настоящем сайте, полным прогоном; после прогона сверить
  числа и то, что фильтры и корзина вернулись как были.
- Прежде чем делать вывод о поведении сайта («сломалось», «сбросилось»), найти
  это место в `obshchee/spravochnik.md`: многое уже измерено.
- Скилл не править по кругу: только то, что реально сломалось в прогоне.
  Задача — чтобы сбор выполнялся, а не совершенствовался.
- Код для страницы правится в `scripts.js`; после правки — `python3 build.py`
  в папке скилла (нужны Node.js и terser; без terser копия соберётся без
  сжатия), проверка — `python3 build.py --check`.
- Решения, с которыми проект передан (подробно — `istoriya.md` скилла):
  «6 скидок» запрашивать и дважды обновлять без вопроса, раз в день; один
  отчёт в день; вопрос «только ВкусВилл или все, включая партнёрские» —
  первым, без чисел, при каждом сборе; корзину пустой не требовать; в чате
  короткая сводка, полные таблицы — в файле; у товаров нет кодов, проценты
  со знаком («−10%»). Хозяин проекта может их поменять — тогда записать в
  `istoriya.md`.
